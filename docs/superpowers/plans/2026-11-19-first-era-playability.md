# First-era playability implementation plan

Goal: an ordinary player can start, understand the next useful action and complete the Stone Age without developer resources. Dima's direct priority supersedes visual/roads/NPC work for this iteration. Preserve all economy values, geography, savev5, historical rewards/readiness, compact menus and gestures. Execute inline with TDD and one final independent review; commit each coherent step.

Design decision: retain seven existing chapters and thresholds. A non-persistent, read-only guidance resolver selects the next incomplete objective and explains necessary research, resource production/modes, construction, staffing, housing or exploration first. Knowledge production must be explained even though the circle belongs to a later chapter. Keep next action visible when goals are collapsed; expansion shows why/how and opens existing Buildings/Research/inspection/resource/population/Explore screens. Actions navigate only; player still confirms real transactions and placement. Show clear era completion with continued sandbox play; no new age.

Alternatives considered: reorder chapter requirements (unnecessary progression change); static tutorial text (cannot diagnose missing production/prerequisites); forced tutorial/auto-buy (reduces freedom). Choose contextual optional guidance, bounded recursion and current catalog/rules, no save fields. Exact recommendation order is an implementation choice; no optimality/enjoyment claim.

- [ ] 1. Commit human priority/approved guidance intent into canonical design documents before code. Establish baseline checks.
- [ ] 2. Add failing guidance regressions (first action, knowledge bootstrap, recipe inputs/modes, recovery, completion/history). Implement a bounded read-only resolver in GameCore; prove an entire ordinary-cost recommendation-following route can finish all catalogs/chapters/pillars and survive reload. Instrument chapter/wait/resource/workforce/action measurements and compare existing routes. No balance tuning without evidence.
- [ ] 3. Cache guidance per actual session state; integrate visible next action and explanatory navigation in existing goals/journey. Test fresh-player guidance→catalog→drag, research prerequisite navigation and completion status. Keep compact menus and native gestures. Commit.
- [ ] 4. Run Debug/Release/core probes and complete final UI suites on phone/mini/Pro; native captures and final read-only review, fix confirmed issues. Build signed update; recheck device availability, backup/validate/install/compare only if possible. Consolidate first-era quality report, limits and canonical status, commit cleanly. Stop at review; no secondary graphics/roads/NPC/footprint expansion.

Review focus: guidance cycles or endless waits, finite resource/cap limits, recipe changes destroying an existing supply, dependency visibility, historical readiness, poor staffing recovery, navigation spending or losing previews, phone HUD/goal clipping, no developer-only APIs leaking toRelease. Regression is about reachable real player behavior, not mirroring the view structure.
